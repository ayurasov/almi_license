# I3-03. Локальный сервер (E09-01…E09-04)

```text
Истории E09-01…E09-04 — четыре ветки по порядку. Общий контекст: раздел 10 docs/specs/01-architecture.md, раздел 13 docs/specs/02-interaction-spec.md, пути /api/sync/v1/* в contracts/openapi-product-api-v1.yaml.

E09-01: в режиме DEPLOYMENT_MODE=local отключить (404) Admin API каталога, импорта ЛК, выпуска ключей; включить мастер первого запуска в консоли (код регистрации, адрес центрального сервера или режим «только файлы»). Один образ — проверка режима через настройку, а не через разные сборки.

E09-02 (на центральном): регистрация — код регистрации (одноразовый, срок 7 дней) → сертификат локального сервера (role=local_server, customer, products) через signing.domain → первый пакет. Онлайн: POST /api/sync/v1/servers/register. Файлом: тот же сервис, вход и выход — файлы.

E09-03 (на локальном): импорт пакета .alk: цепочка корень → ключ выпуска → пакет; seq строго больше текущего; срок пакета; применение квот (Allocation) и отзывов в одной транзакции; онлайн — фоновая задача по расписанию GET /package?since_seq, офлайн — загрузка файла в консоли.

E09-04 (на локальном): Product API работает так же, как на центральном (тот же код api_product); лимиты — по квоте пакета; аренды подписываются ключом локального сервера; срок аренды не позже срока пакета; цепочка в заголовке — сертификат локального сервера.

Тесты для каждой части; сквозной тест E2E: центральный и локальный в одном docker compose, регистрация, пакет, активация lm-demo на локальном сервере.
P7 обязательно для E09-02, E09-03, E09-04.
```
