# ADR-001. Модульный монолит

- Статус: принято (Р1, раздел 5 документа 1)
- Дата: 23.10.2026
- История: E00-08

## Контекст
Нагрузка на сервер лицензирования невелика (тысячи активаций в сутки), команда этапа 1 — несколько человек; микросервисы добавили бы сеть, согласованность и развёртывание без выигрыша.

## Решение
Один Django-проект `server/`; модули `server/apps/<модуль>` (catalog, licensing, activation, policy, packages, signing, stats, audit, iam, outbox, api_product, api_admin, api_sync, compat). Бизнес-логика — в `domain/`; модуль не читает чужие таблицы, обращается только к domain-сервису другого модуля. Внешние ключи между модулями — только licensing → catalog и activation → licensing (решение I1-03).

## Последствия
Границы проверяют import-linter (`server/pyproject.toml`, 4 контракта) и тест `server/tests/test_module_boundaries.py`. Модуль можно выделить в сервис позже, не меняя Product API. Транзакции между модулями — общие (одна БД).
