# ADR-005. `instance_id` и отпечаток с допуском

- Статус: принято (Р5, раздел 5 документа 1)
- Дата: 23.10.2026
- История: E00-08

## Контекст
Привязка только к HWID ломается на виртуальных машинах и в контейнерах, где «железо» меняется; без привязки активацию легко клонировать.

## Решение
Экземпляр идентифицируется `instance_id` (генерируется продуктом, хранится в SecureStore) и отпечатком из 4 компонентов (`disk`, `board`, `cpu`, `mac`) в виде хэшей. Допуск — совпадение не менее 3 из 4; недоступный компонент (`unknown`) не учитывается, тогда не менее 2 из 3 (раздел 2.4 документа 2). Вне допуска — `412 rebind_required`; тот же `instance_id` с другим ключом устройства вне допуска — `409 instance_conflict`.

## Последствия
Хэши компонентов не попадают в журналы (правило 9 `AGENTS.md`). Промпт I2-05 формулировал допуск как «2 из 4»; исправлен по разделу 2.4 документа 2 (23.10.2026). Реализация — `apps/activation/domain/fingerprint.py` (меньше двух сравнимых компонентов — вне допуска).
