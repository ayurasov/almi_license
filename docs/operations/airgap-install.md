# Установка локального сервера в изолированном контуре (E15-04)

Комплект `almi-license-local-<версия>.tar.gz` содержит всё, что нужно для работы без интернета: образы (`docker save`), compose-файл, скрипты и инструкции. Цель — установка на чистый хост за 30 минут.

## Требования к хосту

- Linux x86-64, Docker 24+ с плагином compose, `openssl`, `sha256sum`.
- 2 vCPU, 4 ГБ ОЗУ, 40 ГБ диска.
- Имя сервера в сети заказчика, например `license.corp.local`, и сертификат TLS для него от удостоверяющего центра заказчика. Без сертификата `install.sh` создаст самоподписанный — для пробной установки.

## Установка

1. Перенесите архив на хост и распакуйте его:
   `tar -xzf almi-license-local-<версия>.tar.gz && cd almi-license-local-<версия>`.
2. Проверьте подпись комплекта на доверенной машине: `SHA256SUMS.sig` проверяется утилитой `almi-keytool` открытым ключом выпуска АЛМИ. Сами суммы `install.sh` проверит.
3. Создайте `.env` из `.env.example` и задайте `SERVER_NAME` и при необходимости `HTTPS_PORT`. `TRUST_ROOTS` уже заполнен при сборке, его не меняйте.
4. Положите сертификат и ключ в `tls/server.crt` и `tls/server.key`.
5. Запустите `./install.sh`. Скрипт:
   - проверяет Docker и `SHA256SUMS`;
   - загружает образы;
   - создаёт секреты в `secrets/` (пароль владельца БД, пароль роли приложения, ключ Django, пароль резервных копий);
   - запускает сервисы и выполняет `check.sh`.
6. Создайте администратора консоли (пароль вводится без отображения):
   `docker compose run --rm api manage create_account --username admin --role admin`.
7. Откройте `https://SERVER_NAME/` и пройдите мастер первого запуска:
   - укажите код регистрации от оператора АЛМИ;
   - выберите способ обмена — онлайн или файлами.

## Проверка

`./check.sh` проверяет:
- состояние сервисов `db`, `api`, `worker`, `console`, `gateway`;
- готовность API;
- регистрацию и срок пакета (предупреждение за 30 дней);
- отчёты об использовании;
- заполнение диска;
- возраст последней резервной копии.

Код возврата 1 означает, что нужно вмешательство: причина названа в выводе.

## Резервные копии

- `./backup.sh` — зашифрованная копия в `backups/`.
- Рекомендуемое задание cron: `17 2 * * * /opt/almi/backup.sh`.
- `./restore.sh backups/almi-<время>.dump.gpg` — восстановление.

Пароль копий лежит в `secrets/backup_passphrase`. Сохраните его отдельно от копий: без него копии не восстановить. Подробнее — в `docs/backup.md`.

## Обновление

`./upgrade.sh /путь/к/новому/комплекту`:

1. проверяет суммы нового комплекта;
2. снимает резервную копию;
3. загружает новые образы;
4. применяет миграции.

Если миграция не прошла, скрипт возвращает предыдущую версию.

## Роли базы данных

- `almi` — владелец таблиц: миграции (`migrate`), резервные копии и восстановление.
- `almi_app` — роль API и обработчика задач. Она создаётся и получает права при каждом `migrate` (`manage.py grant_app_role`): чтение и запись таблиц без прав владельца; журнал аудита — только чтение и добавление. Поэтому приложение не может изменить, очистить журнал или отключить его защиту.

## Что хранится где

| Путь | Содержимое | Права |
|---|---|---|
| `secrets/` | Пароль владельца БД (`almi`: миграции, копии), пароль роли приложения (`almi_app`: API и обработчик задач), ключ Django, пароль копий | каталог 0700 |
| `tls/` | Сертификат и ключ TLS | только администратор хоста |
| `backups/` | Зашифрованные копии, `last-success` | только администратор хоста |
| Том `server-key` | Ключ локального сервера (создаёт мастер, 0600) | — |
| Том `db` | Данные PostgreSQL | — |
