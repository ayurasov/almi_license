# Руководство оператора консоли лицензирования (E17-01)

Для операторов и администраторов АЛМИ, работающих в консоли центрального сервера, и для администраторов заказчика на локальном сервере. Описаны экраны и действия этой версии; расхождения со спецификациями — в разделе 13.

## 1. Вход и роли

Консоль открывается по адресу `https://<сервер>/`.

Вход:
- по логину и паролю;
- после 10 неудачных попыток подряд вход блокируется на 15 минут;
- при первом входе с временным паролем консоль требует сменить пароль (экран «Смена пароля»).

Сеанс завершается кнопкой «Выйти» или через 8 часов после входа.

| Роль | Что доступно |
|---|---|
| Оператор | Все экраны, кроме «Пользователи»: заказчики, лицензии, ключи, активации, каталог, профили, импорт, локальные серверы, статистика, журнал |
| Администратор | То же и экран «Пользователи» (учётные записи консоли) |
| Просмотр заказчика | Только свой заказчик: «Лицензии» (карточка без действий), «Статистика», «Журнал» |

Каждое действие, меняющее права, записывается в журнал аудита: кто, когда, с какого адреса, что изменено.

## 2. Заказчики

«Заказчики» — список с фильтрами: наименование, ИНН, статус.

Кнопка «Новый заказчик» открывает форму:
- наименование;
- ИНН (10 или 12 цифр, контрольная сумма проверяется);
- идентификатор в ЛК.

Заказчик в архиве остаётся в отчётах, но новые лицензии на него не создаются. Менеджер заказчика из ЛК показывается продукту АльтерОфис Web в поле `accountManagerInfo`.

## 3. Лицензии

«Лицензии» — список с фильтрами: продукт, заказчик, статус, «Истекает до».

В колонке «Состояние» — что видит продукт:

| Состояние | Значение |
|---|---|
| Активна | Всё работает |
| Скоро истекает | NOTICE: до срока меньше «Уведомлять за» профиля |
| Отсрочка | GRACE: срок прошёл, продукт работает ещё «Льготный период» дней |
| Ограничена | RESTRICTED: отключены функции профиля («Отключаемые функции») |
| Заблокирована | BLOCKED: режим блока профиля, например «только просмотр» |
| Отозвана | REVOKED |

Карточка лицензии открывается кнопкой «Открыть». Вкладки:
- «Параметры»;
- «Ключи»;
- «Активации»;
- «История» — изменения лицензии;
- «Использование»: занято мест, резерв, освобождено автоматически, конфликты, последний контакт, распределение по версиям продукта и ОС.

Действия в карточке:

| Действие | Что происходит | Когда это увидит продукт |
|---|---|---|
| Выпустить ключ | Новый ключ нового образца. Он показывается **один раз** — скопируйте его и передайте заказчику; в базе хранится только хэш и маска | — |
| Продлить | Новые «Действует до», «Поддержка до», число мест; основание (документ) обязательно | При следующей проверке (раз в «Интервал проверки» профиля, по умолчанию 24 ч) |
| Приостановить / Возобновить | Временный запрет с причиной | При следующей проверке |
| Отозвать | Окончательно: лицензию нельзя вернуть. Продукт перейдёт в REVOKED | При следующей проверке |
| Снять блок | Режим «наблюдение» до выбранной даты: ограничения не применяются, продукт продолжает работать | При следующей проверке |
| Режим и лимиты | Число мест, резерв (%), режим («По профилю», «Ограничивать», «Только наблюдать»); для серверного продукта — лимит пользователей и «Считать только активных» | При следующей проверке |
| Перевести | Другому заказчику с указанием основания | При следующей проверке |

Режим «Только наблюдать» (`monitor`) — состояние на этапе внедрения. Продукт показывает сообщения о сроке, но функции не отключает. Отказы учитываются в статистике.

Места:
- Лимит — «Мест» плюс резерв (по умолчанию 3 %, округление вверх).
- Активация сверх лимита, но в пределах резерва помечается «резерв».
- Сверх резерва продукт получает отказ «Превышено количество активаций».
- Места, переданные локальным серверам, на центральном сервере не выдаются.

## 4. Активации

«Активации» — поиск по ID активации, имени компьютера или версии продукта; фильтр по статусу.

Отметки:
- «резерв» — занято место из резерва;
- «файлами» — активация через офлайн-портал;
- «конфликт» — тот же экземпляр продукта появился на другом компьютере (клон). Активная запись при этом не меняется: решите, какую оставить.

Статусы: «Активна», «Освобождена», «Освобождена автоматически» (продукт не выходил на связь «Освобождать место через» дней профиля, по умолчанию 30), «Отозвана», «Конфликт».

«Освободить» освобождает место с указанием причины. Продукт узнает об этом при следующей проверке и перейдёт в режим без лицензии. Пользователь может активировать продукт снова, если есть свободное место.

## 5. Импорт выгрузки ЛК

«Импорт» — пять шагов: загрузка, предпросмотр, сопоставление, подтверждение, отчёт.

1. Выберите XLSX-выгрузку ЛК и нажмите «Загрузить и проверить». Ничего не записывается до подтверждения; ключи показываются маской.
2. Предпросмотр: «Новые», «Изменения», «Без изменений», «Ошибки». У каждой ошибки указаны строка и причина.
3. Сопоставление: каждому артикулу (поле AA) назначаются продукт, редакция и метрика. Сопоставления сохраняются и применяются к следующим выгрузкам. Строки с несопоставленными артикулами не импортируются.
4. «Подтвердить импорт».
5. В отчёте — число созданных и изменённых лицензий, новых заказчиков, строк с ошибками.

Повторный импорт того же файла ничего не меняет.

## 6. Каталог и профили

«Каталог» — продукты, редакции и функции. Начальный каталог загружается при установке (`loadcatalog`):
- АльтерОфис Desktop (`alteroffice-desktop`, редакции standard и professional);
- АльтерОфис Web (`alteroffice-web`, enterprise);
- АльтерОС (`alteros`, workstation).

Функция, переведённая в архив, исчезает из аренды при следующей проверке.

«Профили» — политики лицензирования по продуктам (`<продукт>.<класс>`). Сохранение создаёт новую версию: старые аренды ссылаются на свою версию, история хранится. Параметры:
- режим `enforce` или `monitor`;
- «Уведомлять за», «Льготный период»;
- «После льготного периода» — ничего, отключить функции или блок;
- отключаемые функции и срок ограничения;
- режим блока и функции в режиме просмотра;
- офлайн-запас, интервал проверки, автоосвобождение, резерв.

В разделе «Сообщения» задаются тексты (ru и en) с предпросмотром подстановок. Подстановки: `{days_left}`, `{valid_until}`, `{customer}` и другие по документу 5. Неизвестная подстановка подсвечивается.

На выпуске 1.0 все профили в режиме `monitor`. Перевод в `enforce` — решение владельца продукта после периода наблюдения.

## 7. Офлайн-активация (портал)

Для компьютеров без доступа к серверу:

1. Пользователь создаёт в продукте файл запроса `.alk-req`.
2. Файл загружается на публичной странице `https://<сервер>/offline` (вход не нужен). После нескольких запросов с одного адреса портал попросит ввести капчу.
3. Портал выдаёт файл ответа `.alk-lic`. Его применяют в продукте (в прототипе — `license apply`).

Продление и освобождение — так же, файлами `renew` и `release`. Такая активация занимает место как обычная и отмечена «файлами».

## 8. Локальные серверы

«Локальные серверы» (центральный сервер) — серверы заказчиков в закрытых контурах.

1. «Новый сервер»: заказчик, название, число мест по каждой лицензии.
2. Код регистрации показывается **один раз** и действует 7 дней. Передайте его администратору заказчика; «Новый код» выпускает замену.
3. Обмен по сети: локальный сервер регистрируется сам и получает пакет прав `.alk`.
4. Обмен файлами:
   - «Регистрация файлом»: загрузите `.alk-req` из мастера локального сервера и передайте полученный пакет администратору;
   - отчёты об использовании `.alk-usage` загружаются кнопкой «Загрузить отчёт»; квитанция уходит с ближайшим пакетом.

Состояния: «Ожидает регистрации», «Работает», «Отключён». «Пакет истекает» предупреждает о сроке пакета.

## 9. Консоль локального сервера

На локальном сервере (режим `local`) нет каталога, импорта и выпуска ключей.

- **Первый запуск** (только администратор):
  - введите код регистрации;
  - выберите обмен: «По сети (HTTPS)» с адресом центрального сервера или «Только файлы» — тогда запрос сохранится в файл для оператора АЛМИ.
- **Пакет прав** показывает номер, срок, сервер и способ обмена. Действия:
  - «Загрузить пакет .alk» — пакет с меньшим или тем же номером не принимается;
  - «Проверить обновление»;
  - «Сформировать отчёт» — отчёт об использовании для центрального сервера.

  За 30 дней до срока пакета консоль предупреждает. После срока лицензии работают по правилам пакета: отсрочка 30 дней, затем ограничение.

Продукты заказчика активируются на локальном сервере так же, как на центральном. Аренды подписывает ключ локального сервера.

## 10. Статистика

«Статистика» — фильтры по заказчику и продукту.

Плитки:
- лицензий;
- мест;
- активировано;
- свободно;
- в резерве;
- освобождено автоматически.

В таблице — те же данные по лицензиям; для АльтерОфис Web также пользователи и отметка «Превышен лимит пользователей». Ниже — распределение по версиям продукта и ОС.

«Выгрузить в XLSX» создаёт файл с листами «Сводка» и «Активации» (до 100 000 строк). Время в файле указано в UTC.

## 11. Журнал аудита и пользователи

«Журнал» — фильтры по объекту (лицензия, активация, заказчик, пользователь, локальный сервер, продукт, профиль, импорт, артикул), идентификатору, пользователю, типу события (например, `license.`), периоду. Записи журнала нельзя изменить или удалить; их целостность проверяет цепочка хэшей (`manage.py verify_audit`). «Выгрузить в CSV».

«Пользователи» (администратор):
- создание учётной записи: логин и роль, для роли «Просмотр заказчика» — также заказчик;
- блокировка;
- «Сбросить пароль»: новый пароль показывается один раз, текущие сеансы пользователя завершаются. Пароль передаётся по защищённому каналу, при первом входе его нужно сменить.

## 12. Что делать, если…

| Ситуация | Действие |
|---|---|
| Заказчик сменил компьютер, места нет | Освободите старую активацию («Активации» → «Освободить») |
| Заказчик потерял ключ | «Выпустить ключ». Старый ключ продолжает действовать: отдельно ключ не отзывается, только вся лицензия (раздел 13) |
| Конфликт активации (клон) | Сверьте имя и последний контакт; освободите лишнюю запись |
| Продление оплачено, продукт ещё показывает срок | Продлите лицензию; продукт увидит это при проверке (или «Проверить» в окне лицензии продукта) |
| Продукт заблокирован по ошибке | «Снять блок» до нужной даты — режим наблюдения, затем исправьте условия |
| Заканчивается пакет локального сервера | Продлите лицензии; при обмене файлами передайте администратору новый пакет |

## 13. Расхождения со спецификациями

1. Документ 2, раздел 10: активация по телефону (`LM_ACT_OFFLINE_PHONE`) отнесена к этапу 2; модуль отвечает `LM_ERR_UNSUPPORTED`.
2. Документ 2, раздел 11.1: для АльтерОфис Web на этапе 1 превышение пользователей и окончание срока — только уведомления приложения `support`. Сервер ограничений не накладывает; консоль показывает «Превышен лимит пользователей».
3. Конкурентные места (`seats:*`) и Integration API для ЛК описаны в контракте как этап 2 и не реализованы (`make contract-check` проверяет, что они не обслуживаются).
4. Подсказка пустого каталога в консоли ссылается на `make seed` (команду разработчика). На установленном сервере каталог загружает `install.sh`.
5. Экспорт журнала — CSV, статистики — XLSX; формат журнала в спецификации не задан.
6. Отдельный ключ лицензии нельзя отозвать: отзывается вся лицензия. Утечка ключа сдерживается лимитом мест и журналом активаций; при необходимости — новая лицензия и перенос активаций.
