## 1. Итог

1. **Препятствий со стороны сторонних компонентов не выявлено.**
   - Все 134 сторонних компонента приложения и модуля DL распространяются под открытыми (свободными) лицензиями: 129 — под разрешительными, 5 — под LGPL.
   - Компонентов под проприетарными, коммерческими, «несвободными» лицензиями и лицензиями с территориальными ограничениями нет.
   - Платежей иностранным правообладателям за компоненты нет.
2. **Модуль DL**, который встраивается в АльтерОфис и другие продукты, связан только с библиотеками под разрешительными лицензиями. Это libsodium (ISC), curl (curl), OpenSSL (Apache-2.0, только Linux), zlib (Zlib), nlohmann/json (MIT). Ограничений на лицензирование продуктов, в которые он встроен, они не накладывают.
3. **Во время работы ПО не обращается к зарубежным сервисам.**
   - Нет телеметрии, внешних CDN, шрифтов или обновлений из-за рубежа.
   - Сервер и модуль работают с адресами, которые задаёт правообладатель или заказчик: `license.alter-os.ru` или локальный сервер.
   - Комплект локального сервера устанавливается и работает без доступа в интернет.
4. **Есть три зависимости от зарубежной инфраструктуры — на этапе сборки, а не работы.** Это Docker Hub, PyPI, npm, GitHub (vcpkg) и CI GitHub Actions. На регистрацию они, по нашему пониманию, не влияют, но могут стать вопросом эксперта и являются риском непрерывности. Рекомендации — в разделе 5.
5. **Нужно подготовить к заявке:**
   - документы о принадлежности исключительного права на собственный код;
   - перечень сторонних компонентов (готов — этот SBOM);
   - выполнение условий открытых лицензий (notices готовы, раздел 4).

## 2. Что проверялось и как

### 2.1. Что требует реестр

Ниже — требования, на которые влияет состав ПО. Номера пунктов и формулировки сверяет юрист по действующей редакции.

### 2.2. Метод

- **Состав** — SBOM CycloneDX (`docs/sbom.md`). Образы проверяет Syft, модуль DL — дерево vcpkg, библиотеки внутри колёс Python — `tools/sbom/vendored.json`.
- **Лицензии** классифицированы по политике `tools/sbom/license-policy.json`:
  - разрешительные;
  - слабый копилефт;
  - сильный копилефт;
  - сетевой копилефт;
  - не открытые;
  - не определённые.
- **Обращения во время работы** проверены по коду: поиск внешних адресов в коде сервера, консоли, модуля DL и комплектов. Найдены только `license.alter-os.ru`, адреса внутри сети compose и примеры (`license.corp.local`).
- **«Протестные» пакеты** (protestware). Перечень npm-зависимостей консоли, включая инструменты разработки (426 пакетов), сверен с известными случаями: `node-ipc`, `peacenotwar`, `es5-ext`, `event-source-polyfill`, `colors`, `faker`. Ни одного из них нет.

## 3. Результаты

### 3.1. Лицензии по видам поставки

| Вид поставки | Компонентов | Разрешительные | Слабый копилефт | Сильный копилефт | Сетевой, не открытые, не определённые |
|---|---|---|---|---|---|
| Модуль DL (связывается с продуктами) | 9 (5 Linux, 4 Windows) | 9 | 0 | 0 | 0 |
| Приложение: пакеты Python и npm, библиотеки внутри колёс, almi-keytool | 125 | 120 | 5 | 0 | 0 |
| Пакеты ОС базовых образов (Debian), включая образы PostgreSQL и Nginx | 540 | 137 | 57 | 346 | 0 |
| Инструменты разработки и CI (не поставляются) | 352 | 350 | 2 | 0 | 0 |

Слабый копилефт в приложении:

| Компонент | Лицензия | Как используется |
|---|---|---|
| psycopg 3.3.6, psycopg-binary 3.3.6, psycopg-pool 3.3.3 | LGPL-3.0-only | Драйвер PostgreSQL, модуль Python, без изменений |
| keyutils, libxcrypt (внутри psycopg-binary) | LGPL-2.1-or-later | Разделяемые библиотеки колеса, загружаются динамически |

LGPL допускает использование в несвободном продукте, если библиотека не изменяется и может быть заменена пользователем. Условия выполняются: библиотеки не изменены, загружаются динамически, тексты лицензий входят в notices. Исходные тексты той же версии доступны в PyPI и в проектах, указанных в SBOM.

### 3.2. Лицензии с ограничениями

- **Территориальные и санкционные ограничения.** Ни одна лицензия в составе не содержит запрета на использование в РФ или по признаку страны, организации или отрасли. Лицензии вида «не для коммерческого использования» (CC-BY-NC), с ограничением конкуренции (BUSL, Elastic, Commons Clause) и проприетарные отсутствуют — проверено политикой: категории «не открытая» и «сетевой копилефт» пусты во всех артефактах.
- **Сильный копилефт (GPL).** Встречается только в пакетах ОС базовых образов: coreutils, bash, apt, util-linux и т. п.
  - Это отдельные программы ОС, с кодом продукта они не связываются. Продукт обращается к ним, как любая программа к ОС.
  - Образы передаются без изменений, тексты лицензий лежат в `/usr/share/doc/*/copyright`, исходные тексты — в архиве Debian.
  - На лицензирование продукта GPL этих программ не распространяется.
  - Счёт завышен: Syft относит пакет к GPL, если GPL упомянута в его файле copyright хотя бы для одного файла. Так, `libssl3`, `libsqlite3` попадают в «сильный копилефт» из-за файлов сборки.

### 3.3. Независимость работы от зарубежных сервисов

| Проверка | Результат |
|---|---|
| Обращения сервера во время работы | Только к своей базе данных; к центральному серверу АЛМИ — только локальный сервер, по адресу из регистрации |
| Модуль DL | Только к серверу лицензирования из настроек продукта или команды «Перевести на другой сервер» (принимается только `https`). Загрузки кода нет; обновление ключей доверия — пакетом доверия, подписанным корнем АЛМИ |
| Консоль | Статика из образа; шрифты системные, значки PrimeIcons входят в сборку; внешних CDN и счётчиков нет |
| Обновление ПО | Только администратором: `upgrade.sh`, комплект изолированного контура. Автоматического обновления нет |
| Работа без интернета | Комплект локального сервера: образы внутри архива, установка и работа без внешней сети (CI `airgap-bundle`) |

### 3.4. Собственный код

SBOM перечисляет только сторонние компоненты. Собственный код — сервер, консоль, модуль DL, keytool, скрипты комплектов — в SBOM представлен самими артефактами.

Для заявки правообладатель подтверждает исключительное право на этот код:
- трудовые договоры и служебные задания;
- договоры с подрядчиками об отчуждении права;
- описание процесса разработки.

Это организационный вопрос, состав сторонних компонентов на него не влияет.

## 4. Условия открытых лицензий: что уже выполнено

| Условие | Где выполнено |
|---|---|
| Сохранение уведомлений об авторских правах и текстов лицензий (MIT, BSD, Apache-2.0, ISC и др.) | `notices/` в SBOM: Python-пакеты образа сервера и keytool, npm-пакеты консоли, библиотеки модуля DL. Пакеты ОС — внутри образов (`/usr/share/doc`) |
| Notices модуля DL в продуктах | Требование в `docs/integration/product-guide.md`: файл кладётся в дистрибутив продукта |
| Файл NOTICE лицензии Apache-2.0 | Входит в notices, если пакет его содержит: собираются файлы `NOTICE*` |
| LGPL: возможность замены библиотеки, доступ к исходным текстам | Раздел 3.1 |
| Перечень сторонних компонентов для эксперта | `sbom-report.md`, `sbom-components.csv` и приложение А этого документа |

Два npm-пакета не прикладывают файл лицензии — это MIT-пакеты с лицензией только в метаданных. Notices это отмечают.

## 5. Риски и рекомендации

| № | Риск | Влияние | Рекомендация |
|---|---|---|---|
| 1 | Сборка зависит от зарубежных репозиториев: Docker Hub (базовые образы), PyPI, npm, GitHub (исходники vcpkg), GitHub Actions (CI) | На работу ПО не влияет. При блокировке или недоступности невозможно выпустить обновление; эксперт может спросить о воспроизводимости сборки | Зеркала в контуре правообладателя: реестр образов, прокси PyPI и npm (Nexus, Harbor или аналоги из реестра), кэш исходников vcpkg (`X_VCPKG_ASSET_SOURCES`); CI на российской платформе или своём сервере; фиксация дайджестов базовых образов |
| 2 | Базовые образы на Debian (`python:3.13-slim`, `nginx:1.27`, `postgres:17`) | Debian — свободное ПО сообщества, не иностранный правообладатель. При требовании заказчика к отечественной ОС в составе возникнет вопрос | Подготовить вариант образов на ОС из реестра. Логичный кандидат — АльтерОС, если у неё есть контейнерный базовый образ; иначе другие ОС из реестра. Сборка сервера от базового образа не зависит, кроме пакетов `apt` в `deploy/Dockerfile` |
| 3 | Криптография модуля и сервера — Ed25519 (libsodium, cryptography), не ГОСТ | Для реестра не требуется. Может стать вопросом при сертификации ФСТЭК или ФСБ и у заказчиков с требованием ГОСТ | Вне этапа 1; при необходимости — профиль подписи ГОСТ Р 34.10-2012 через СКЗИ из реестра (изменение контракта аренды) |
| 4 | Лицензии части библиотек ОС установлены вручную (`overrides`) | Ошибка установления приведёт к неверному выводу | Источник каждой записи указан в политике; юристу — выборочная сверка по `/usr/share/doc/*/copyright` |
| 5 | Новые зависимости меняют состав | Перечень устаревает | SBOM собирается в CI на каждом запросе на слияние; нарушение политики останавливает слияние. К заявке прикладывается SBOM выпуска (`make sbom VERSION=…`) |

## 6. Что приложить к заявке (технически)

1. SBOM выпуска (`dist/sbom`): CycloneDX по артефактам, `sbom-report.md`, `sbom-components.csv`, notices, `SHA256SUMS`.
2. Этот документ: аналитика состава и независимости от зарубежных сервисов.
3. Описание архитектуры и развёртывания: `docs/deployment.md`, `docs/operations/airgap-install.md`.
4. Руководство пользователя: `docs/user-guide.md`; документы DOCX и PDF — `make guides`.
