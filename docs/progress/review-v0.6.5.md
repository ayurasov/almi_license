## 4. Нужно решение руководителя проекта

Решено 29.10.2026 и сделано в v0.6.6: В1 — векторы добавлены; В2 — отказ активаций с кодом `license_suspended`; В3 — права на локальном сервере только из пакета. Открыты В4–В7.

| № | Вопрос | Суть | Предложение |
|---|---|---|---|
| В1 | Векторы контракта для ролей цепочки | Шаг 5 `contracts/vectors/README.md` не называет роли; правило теперь в коде всех трёх проверяющих | Задача с меткой contract: уточнить шаг 5 и добавить векторы «ключ локального сервера выпустил issuer» и «issuer выпустил issuer» (добавляющее изменение) |
| В2 | Что значит «Приостановлена» | Статус не влияет ни на что: сервер и DL его не учитывают (вопрос 12: состояние по датам). Руководство обещает «временный запрет». На локальном сервере так помечаются лицензии, убранные из пакета, — и они продолжают работать | Отказ новых активаций и проверок (`license_suspended` нет в каталоге раздела 16 — нужен код или `license_revoked`); либо убрать действие из консоли |
| В3 | Права на локальном сервере | Admin API локального сервера позволяет создать лицензию, продлить, поднять лимит мест, перевести — без пакета; аренды подписывает ключ сервера. Документ 1, раздел 9.1: «не может выдать больше, чем в пакете» | Закрыть эти действия в режиме local (`central_only`), оставить приостановку и отзыв |
| В4 | Резерв мест при квотах | Резерв считается отдельно на центральном и на каждом локальном сервере: лимит 10 и 10 серверов по 1 месту дают 20 мест вместо 11 (раздел 5.2 п. 4) | Резерв только на центральном сервере, в пакете `reserve_pct = 0`; или делить резерв квотой |
| В5 | Состояние после `release` | Документ 2, разделы 5.4 и 8: после освобождения — `UNLICENSED`; модуль переходит в TRIAL по разделу 7.2, если не прошло 30 дней с установки. Компьютер, освобождённый оператором, работает дальше с полным набором функций | Раздел 5.4 приоритетнее: после `release` пробный период не возобновляется |
| В6 | `instance_conflict` | Документ 5 предлагает «Активировать заново», но в C ABI нет способа получить новый `instance_id`: клон ВМ остаётся заблокированным | Новая функция ABI `LM_ResetInstance` (добавление в конец, правило 15) |
| В7 | Блокировка входа в консоль | Документ 1, §12: после 5 неудач; бэклог E07-02 и код: после 10 | Выбрать одно значение |

## 5. Отмечено, не исправлено (по важности)

- Подпись запросов локального сервера к центральному, `.alk-req` и `.alk-usage` — сырым ключом в обход `CryptoProvider` и без канонического JSON (правило 12, раздел 6.5 документа 1). Нужен перенос в провайдер; решения для этих путей нет.
- Нет `KeyStore` (разделы 6.4–6.5 документа 1): ключи читаются из файлов напрямую.
- Предел тела запроса Product API 256 КБ (раздел 4.2) не соблюдается: принимается до 2,5 МБ, сверх — ответ 400 Django, а не `413 payload_too_large`.
- Импорт пакета не пересчитывает состояния сразу (раздел 13.3), только ежечасной задачей; лицензии вне пакета приостанавливаются без отдельного события аудита.
- Центральный сервер не сверяет отчёт `.alk-usage` с квотами (число активных против выделенных мест).
- Капча одноразова только без гонки (чтение и удаление — два запроса); лимит на ключ в адаптерах compat различает регистр и пробелы ключа.
- Повтор офлайн-файла `activate` после освобождения снова занимает место в течение срока файла.
- Офлайн-сценарий и решение о капче собраны в представлении (правило 2).
- Тесты: директива `rebind` не проверяется ни в DL, ни в сквозных сценариях; коды раздела 16 401 `clock_skew`, 403, 404, 409 `instance_conflict`, 412, 413, 422, 426, 429 не проверяются на стороне модуля; `config.json` модуля (пункт 1 раздела 18) — только переменной окружения прототипа.
- Проверка совместимости с ЛК замкнута: фикстуры `server/tests/compat` — предварительные (вопрос 16), прототипы и адаптеры построены по одному описанию. Зелёные сценарии не доказывают совместимость с настоящими `registration.sh` и приложением `support`.
- mini-office: блокирующие вызовы (`LM_Activate`, `LM_CheckNow`) в основном потоке; ошибки печатаются с кодом в основном тексте (документ 5, §2 п. 4).

## 6. Что соответствует

Границы модулей (import-linter ловит внесённые нарушения), время только через `Clock`, чистота PolicyEngine, блокировки мест в активации, проверке, освобождении и автоосвобождении (один порядок блокировок, без взаимных), аудит изменений прав, коды ошибок только из каталога, обратимые миграции, закрытие каталога, импорта и выпуска ключей в режиме local на сервере, подпись запросов (окно ±300 с, `nonce` после проверки подписи, тело до разбора), Idempotency-Key, состав аренды, импорт пакета до записи, отчёты `.alk-usage`, регистрация локального сервера, хранение ключей лицензий (хэш и маска), IAM (Argon2id, сессии, CSRF), очередь задач.
