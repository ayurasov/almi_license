# Подключение продукта к системе лицензирования (E17-03)

Руководство для команды продукта: АльтерОфис Desktop и другие продукты на модуле DL. Источник истины — раздел 15 (C ABI) и раздел 18 (чек-лист соответствия) документа 2. Здесь — порядок работы и то, чем проверить подключение.

## 1. Что получает продукт

| Артефакт | Где | Назначение |
|---|---|---|
| `license_module.dll` / `liblicense_module.so` и `include/license_module.h` | артефакт CI `license_module-*` (сборка с корнем `prod` — при выпуске после E17-04) | Модуль, C ABI v1 |
| `license_module_stub` | артефакт CI | Заглушка с теми же функциями: продукт можно собирать и запускать до подключения сервера |
| `lm-demo` | артефакт CI | Консольный пример: все режимы через C ABI, образец вызовов |
| `build/sbom/dl/license_module-<платформа>.cdx.json`, `build/sbom/notices/license_module-<платформа>.txt` | тот же артефакт CI | SBOM модуля (CycloneDX) и тексты лицензий связанных с ним библиотек: libsodium, curl, OpenSSL (Linux), zlib, nlohmann/json (`docs/sbom.md`) |

Модуль связан с этими библиотеками статически, все их лицензии разрешительные. Они требуют сохранять уведомления об авторских правах: файл `license_module-<платформа>.txt` входит в дистрибутив продукта рядом с модулем или в общий файл сторонних лицензий продукта.

## 2. Порядок вызовов

1. **Запуск.** Один раз до показа основного окна вызовите `LM_InitializeEx` с `struct_size`, `product_code`, `app_version`. `server_url` и `data_dir` по умолчанию берутся из ОС и `config.json`; адрес сервера задаётся конфигурацией, без пересборки (пункт 1 чек-листа).
   - `LM_OK` — работаем.
   - `LM_ERR_STORE_CORRUPTED` — модуль работает, но активация утрачена: предложите активировать снова.
   - Проверка при запуске локальная, не дольше 50 мс; проверка на сервере идёт в фоне. Флаг `LM_FLAG_NO_BACKGROUND_CHECK` выключает её, это нужно только утилитам.
2. **Состояние.** Режим, срок и сообщения даёт `LM_GetStatusEx`. Функции ограничиваются только через `LM_HasFeature("имя")` (пункт 9). Тексты `LM_GetMessage` показываются без изменений (пункт 14). Об изменениях сообщает `LM_SetCallback`, например `LM_EVENT_STATE_CHANGED`.
3. **Активация.**
   - Онлайн: `LM_Activate(key, LM_ACT_ONLINE)`.
   - Файлами: `LM_GenerateOfflineRequest(key, path)` → пользователь загружает `.alk-req` на портале `/offline` → `LM_ActivateFromFile(path_to_alk_lic)`.
   - Повторная активация того же компьютера места не занимает (пункт 3).
4. **Проверка.** Модуль сам проверяет лицензию по `next_check_at` и повторяет запрос при ошибках. Без сети продукт работает по сохранённой аренде в пределах политики (пункт 5). `LM_CheckNow` — только по действию пользователя.
5. **Деинсталляция.** Вызовите `LM_Deactivate` (без сети — `LM_GenerateReleaseRequest`), место освобождается (пункт 15).
6. **Завершение.** `LM_Shutdown`.

## 3. Состояния и интерфейс

| `LM_LicenseMode` | Что показывает продукт (раздел 15.4) |
|---|---|
| `TRIAL` | Баннер триала с числом дней |
| `FULL`, `NOTICE` | Работа; при `NOTICE` — напоминание о сроке |
| `GRACE` | Работа и предупреждение об окончании отсрочки |
| `LIMITED (RESTRICTED)` | Функции из `restricted_caps` недоступны (`LM_HasFeature` = 0), остальное работает |
| `BLOCKED`, `SOFT_BLOCK` | Только чтение (`read_only_caps`) или запрет запуска (`no_start`) — по профилю |
| `REVOKED` | Сообщение об отзыве и предложение активировать другой ключ |

В режиме `monitor` (`enforcement_monitor = 1`) функции не ограничиваются, сообщения показываются (пункт 10). Неизвестный режим или функцию продукт показывает как «нет лицензии» и не падает (пункт 13).

## 4. Коды ошибок

| Код | Действие продукта |
|---|---|
| `LM_ERR_INVALID_KEY`, `LM_ERR_EXPIRED`, `LM_ERR_REVOKED`, `LM_ERR_DEVICE_LIMIT`, `LM_ERR_INSTANCE_CONFLICT` | Показать `LM_GetLastError` (текст сервера) |
| `LM_ERR_NETWORK`, `LM_ERR_RATE_LIMITED` | «Сервер недоступен», предложить офлайн-активацию; работа по аренде продолжается |
| `LM_ERR_INVALID_SIGNATURE`, `LM_ERR_INVALID_FILE` | «Файл повреждён или не для этого компьютера» |
| `LM_ERR_UPGRADE_REQUIRED` | Предложить обновить продукт; работа по аренде продолжается |
| `LM_ERR_STORE_CORRUPTED` | Только при запуске: предложить активировать снова |

Повторы, `Retry-After` и повторную активацию после 410/412 модуль выполняет сам (раздел 16).

## 5. Проверка подключения

| Чем | Что проверяет | Пункты раздела 18 |
|---|---|---|
| `lm-demo` и сценарии `tests/e2e` (`make e2e-stand`) против стенда | онлайн- и офлайн-активация, проверка, освобождение, автоосвобождение, политика, `monitor`, триал, локальный сервер | 1, 3, 4, 5, 8, 10, 11, 15, 20 |
| Тесты модуля (`make test-dl`, векторы `contracts/vectors`) | подпись, `aud`, `instance_id`, `seq`, перевод часов, директивы, неизвестные поля и коды | 6, 7, 12, 13, 16 |
| Сценарий 14 `tests/e2e` и разбор журналов продукта | нет ключа, аренды и закрытого ключа устройства в журналах | 17 |
| Замер `LM_InitializeEx` + `LM_GetStatusEx` в продукте | не дольше 50 мс | 18 |
| Ручной тест в сети заказчика | системный прокси, корпоративный корневой сертификат (Windows — хранилище сертификатов ОС) | 19 |

Продукт подключён, когда все 20 пунктов подтверждены. Протокол прикладывается к выпуску продукта.

## 6. Что не делать

- Не хранить ключ лицензии и аренду вне модуля и не писать их в журналы.
- Не вычислять состояние лицензии самому: только `LM_GetStatusEx` и `LM_HasFeature`.
- Не задавать `data_dir` внутри каталога установки: при обновлении продукта активация потеряется. Метка триала от `data_dir` не зависит.
- Не поставлять модуль без файла уведомлений его библиотек (раздел 1).

## 7. Образцы

Прототипы `prototypes/` показывают все вызовы на коротком коде:
- `mini-office` — C ABI модуля, как в АльтерОфис Desktop;
- `mini-web` — запрос подписки Nextcloud;
- `mini-os` — регистрация АльтерОС.

Сценарии ручной проверки и таблица «что куда переносить» — в `prototypes/README.md`. Пробный сервер для них разворачивается по `docs/deployment.md` (`DEV_ISSUER=1`, `seed_minimal`).
